## Milestone 1 — Device B Recorder Foundation (`:recorder-app`)
- **Segmented AES-256-GCM Storage:** Instead of writing unencrypted `.wav` files then encrypting post-hoc, PCM frames are wrapped with a 44-byte RIFF WAV header in memory and encrypted in 64 KB AES-256-GCM chunks using an Android Keystore key (`AES/GCM/NoPadding`) with AAD binding (`segmentId|sessionId|sequenceNumber|chunkIndex`) into `.enc.tmp` followed by atomic rename to `.enc`.
- **Unclean Process Kill Detection:** `RecorderService` persists an active session marker (`activeSessionId`, `lastHeartbeatAt`) in DataStore. If the process is killed by OEM/LMK without `STOPPING`, the next launch or `BootCheckReceiver` reconciles the unclosed `RecordingSession` to `INTERRUPTED` (`PROCESS_KILLED`), transitions `RecorderState` to `SERVICE_INTERRUPTED` (never falsely showing `ARMED`), and logs a `DiagnosticEvent`.
- **Hardware Silence & Contention Guard:** `AudioCaptureEngine` registers `AudioManager.AudioRecordingCallback` (guaranteed on `minSdk >= 29`) to immediately seal any in-progress speech segment and transition to `AUDIO_SILENCED` when `isClientSilenced()` becomes true, resuming only when unsilenced while still authorized.
- **APK Size Note (Observed in M1):** `recorder-app-debug.apk` built to ~127 MB because `onnxruntime-android` bundles native `.so` libraries across all ABIs (`arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`). We will add ABI splits / release minification in Milestone 6.
- **JDK Toolchain Note (Observed in M1):** Removed `jvmToolchain(17)` in `shared-protocol/build.gradle.kts` in favor of `compilerOptions { jvmTarget.set(JvmTarget.JVM_17) }` so Gradle builds cleanly under Android Studio JBR 21 without requiring a separate system JDK 17 installation on `PATH`.
- **Storage Durability & Keystore Compatibility Fix (Post-M1):** Fixed `BufferedOutputStream.close()` closing the underlying `FileOutputStream` prior to `fos.fd.sync()` (which caused `SyncFailedException` on first segment write), moved `SegmentCrypto` to Android Keystore envelope encryption (wrapping per-segment 256-bit DEK with Keystore's randomized IV), and added a generation token to `AudioCaptureEngine` to eliminate stop/start cleanup races.

## Milestone 2 — BLE Control & Pairing (`:shared-protocol`, `:recorder-app`, `:primary-app`)
- **Separate BLE Host Service (`connectedDevice` FGS):** Hosted `BluetoothGattServer` and BLE Advertising inside `BlePeripheralService` (`foregroundServiceType="connectedDevice"`) independently from `RecorderService` (`microphone` FGS), preventing BLE disconnects from touching recording state while avoiding Android 15/16 `dataSync` 6-hour timeouts.
- **ECDH P-256 + 6-Digit SAS + Session Challenge-Response:** Paired devices perform ECDH P-256 + HKDF-SHA256 key derivation with mutual 6-digit SAS confirmation and Android Bluetooth bonding (`createBond()`), followed by per-connection `AUTH_CHALLENGE` / `AUTH_VERIFY` deriving ephemeral `SessionKeys` (`HMAC-SHA256`).
- **Authorized Standby & Local-Capture-Only Mode:** Remote `START_RECORDING` resumes an already-authorized `RecorderService` in `ARMED` standby (or starts listening if idle inside the active service), and returns `SERVICE_NOT_RUNNING` when `RecorderService` is stopped (per Android 14–16 background mic restrictions). Added `localOnlyPauseSync` in `RecorderConfigPayload` (`SET_CONFIG`) so Device A can pause sync/transcript processing while Device B keeps capturing and flushing encrypted audio chunks locally, separate from `STOP_RECORDING` (`STOP_SERVICE` / `STANDBY_PAUSE`).
- **RPA MAC Rotation Resilience:** Device B broadcasts an 8-byte `SHA-256(deviceId)` `deviceTag` in BLE Scan Response Service Data, allowing Device A to re-resolve Device B by application identity if BLE MAC addresses rotate.
- **31-Byte Legacy BLE Advertising Fix:** Switched `deviceTag` beacon from 128-bit `ServiceData` (26B) to 12-byte Manufacturer Data (`BLE_MANUFACTURER_ID = 0x7D2E`) with UTF-8 device-name length budgeting and automatic name-free retry fallback, resolving `ADVERTISE_FAILED_DATA_TOO_LARGE (errorCode=1)`.

## Milestones 3 & 4 — Resilience, Incremental Audio Sync & Device A ASR (`:shared-protocol`, `:recorder-app`, `:primary-app`)
- **Dual-Transport Encrypted Audio Sync (`L2capSyncFraming`):** Device B negotiates an ephemeral BLE L2CAP CoC channel (`listenUsingL2capChannel()`, API 29+) via `SYNC_DATA` and streams AES-256-GCM encrypted WAV chunks using the session encryption key, with automatic seamless fallback to GATT `FETCH_SEGMENT_CHUNK` if L2CAP fails on a given chipset.
- **Resumable Transfers & Integrity-Before-ACK:** Device A writes incoming chunks into `.wav.part` staging files (resuming from `partFile.length()` on reconnect), verifies SHA-256 against Device B's manifest before encrypting into Device A's Android Keystore storage, inserts into Room (`PrimaryDatabase` v2 with non-destructive `MIGRATION_1_2` preserving existing paired devices), and only then sends `SYNC_ACK`. Device B quarantines corrupt local files during sync instead of deadlocking the queue and never deletes segments unless verified `SYNC_ACK` arrives and `autoDeleteSyncedSegments` is enabled.
- **Pluggable Device A ASR (English & Hindi):** Built behind `AsrProvider` with three concrete modes:
  1. `OpenAiWhisperAsrProvider` (`/v1/audio/transcriptions`, `whisper-1` / `gpt-4o-mini-transcribe`, Keystore-encrypted API key),
  2. `LocalWhisperServerAsrProvider` (OpenAI-compatible LAN/on-device `whisper.cpp` / `faster-whisper` endpoint),
  3. `AndroidOnDeviceAsrProvider` (Android 13+ `SpeechRecognizer.createOnDeviceSpeechRecognizer` streaming 16 kHz PCM via `RecognizerIntent.EXTRA_AUDIO_SOURCE`).
  ASR failure always preserves the synced encrypted audio with one-tap retry and local WAV playback preview.

## Live Dual-Device Hardware Verification Fixes (Android 17 Motorola edge 70 fusion ↔ Android 14 OnePlus CPH2401)
- **GATT 512-Byte Attribute Ceiling (`BleChunkFraming.MAX_GATT_VALUE_BYTES = 500`):** Android 14–17 negotiates ATT MTU = `517` (`517 - 3 = 514`), which exceeds Bluetooth Core Spec Vol 3 Part F Section 3.2.9's 512-octet attribute value ceiling by 2 bytes and caused silent truncation on multi-chunk `PAIR_EXCHANGE` ACK notifications. Capping GATT frames at `500` bytes resolved multi-chunk notifications cleanly.
- **Missing Kotlin Serialization Plugin in `:recorder-app`:** Live SAS approval on Device B uncovered missing `alias(libs.plugins.kotlin.serialization)` in `recorder-app/build.gradle.kts` (`PersistedPairingRecord` threw `SerializationException` on disk save). Added the plugin and a regression unit test (`PairingSerializationTest`).
- **Sync State Gate & Insecure L2CAP CoC with App-Layer AES-256-GCM:** Enabled `allowDuringSync = true` on `SYNC_DATA` manifest requests for multi-batch sync, and switched L2CAP CoC channels to `listenUsingInsecureL2capChannel()` / `createInsecureL2capChannel(psm)` because all L2CAP frames are already end-to-end AES-256-GCM encrypted with ephemeral ECDH session keys (avoiding OS SMP bond-state stalls). Verified 24/24 segments (~18 MB across 3 automatic batches) synced over L2CAP CoC at ~32 KB/s with 100% SHA-256 verification and `SYNC_ACK`.
- **Warm OS-Bonded ACL Reconnect Auth (`BlePeripheralManager`):** When Device A and Device B are OS-bonded, system Bluetooth services keep the LE ACL link warm so `onConnectionStateChange(STATE_DISCONNECTED)` may not fire when Device A restarts or reconnects. Replaced the permanent `authChallengeInFlight` flag with a 1.5s debounced CCCD re-subscribe handshake trigger that clears stale session state and immediately issues a fresh `AUTH_CHALLENGE`.
- **Android 13–17 Segmented On-Device Speech (Google SODA):** Upgraded `AndroidOnDeviceAsrProvider` to pass `RecognizerIntent.EXTRA_SEGMENTED_SESSION = EXTRA_AUDIO_SOURCE`, handle `onSegmentResults` + `onEndOfSegmentedSession` + `onPartialResults` fallback, stream PCM in gently paced 100ms (3,200B) chunks with 1.0s trailing silence, ignore SODA's `-1.0f` unknown confidence sentinel, and reset interrupted `PROCESSING` rows on `TranscriptionCoordinator` startup. Verified live offline Hinglish/English transcription + memory extraction + summaries + zero-fabrication Ask AI on Device A.
